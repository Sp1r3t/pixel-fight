# Пиксель-арт бойцов

**Новая версия:** `node tools/pixelart/generate-arcade.js` создаёт полностью
переработанную коллекцию в `art/sprites/v3/`: 16 бойцов, 20 анимаций;
обычные по 16 кадров, ульта по 64 кадра.
Просмотр — `art/sprites/v3/preview.html`; подключение новых ID описано в
`art/sprites/v3/README.md`. Иконки: `node tools/pixelart/generate-icons.js`.
Ниже сохранена документация предыдущего генератора v1 и его уже загруженных листов.

Процедурный генератор пиксель-арт спрайт-листов для всех 16 персонажей. Не требует
Python/внешних библиотек — чистый Node.js (нужен только `node`, PNG кодируется вручную
через встроенный `zlib`).

## Что это и почему так

Боевая система (`src/client/Sprites/SpriteAnimator.luau`) умеет показывать бойца двумя
способами:

- **Rig** (`src/client/Sprites/Rig.luau`) — процедурный «силуэт» из скруглённых прямоугольников.
  Использовался как временная заглушка, пока не было рисованного арта.
- **Sheet** (`src/client/Sprites/SheetSprite.luau`) — обычный спрайт-лист (`ImageLabel` +
  `ImageRectOffset/Size`, `Pixelated`-семплинг). Включается, как только у персонажа задано
  поле `sprites` (`rbxassetid://…`).

Этот генератор рисует картинки для второго варианта: те же позы и та же хореография ударов,
что уже были продуманы в `RigPoses.luau` (портированы в `data/poses.js` — можно проверить,
что цифры совпадают 1:1) и тот же облик/аутфиты из `CharacterLooks.luau`
(портированы в `data/looks.js`), но рисует их как настоящий пиксель-арт, а не гладкие фигуры:

1. Рисует персонажа в супер-разрешении (`--ss`, по умолчанию ×6) чёткими (без сглаживания)
   полигонами/капсулами/кругами — `lib/canvas.js`.
2. Даунсемплит боксом до размера кадра (`--frame`, по умолчанию 120px) — края становятся мягкими.
3. Квантует каждый пиксель к ближайшему из **реально использованных при рисовании** цветов —
   получаются плоские заливки без размытых промежуточных оттенков (главное отличие от «гладких
   фигур»).
4. Обводит силуэт на 1px тёмным контуром — как в классических спрайтах файтингов.

## Запуск

```bash
node tools/pixelart/generate.js              # все 16 персонажей
node tools/pixelart/generate.js rook          # только один — для быстрой проверки/итерации
node tools/pixelart/generate.js rook --frame=120 --ss=6   # другое качество/разрешение
```

Результат — `art/sprites/<id>_a.png` и `art/sprites/<id>_b.png` (**два** листа на персонажа)
в корне репозитория.

**Почему два файла, а не один.** Roblox пересжимает/портит текстуры со стороной больше
~1024px — на одном листе с 12 рядами при детальном кадре высота быстро упирается в этот
предел (на 96px было 1152px — именно это ломало игру: координаты кадров (ImageRectOffset)
съезжали, персонажи выглядели «рваными»/задвоенными). Поэтому раскладка режется пополам по
рядам, и оба файла держатся заметно ниже 1024px по каждой стороне:

```
_a.png (720×720) — ряды 0..5:  0 Idle(6) 1 Walk(6) 2 Dash(4) 3 Jump(4) 4 Crouch(2) 5 Block(2)
_b.png (960×720) — ряды 6..11: 0 Light(4) 1 Heavy(5) 2 Special(6) 3 Super(8) 4 Hit(2) 5 Knockdown(4)
```

С точки зрения игры это по-прежнему один лист 0..11 — `SheetSprite.luau` сам выбирает `_a`/`_b`
по номеру ряда нужной анимации (`Types.SpriteSheet.image2`/`splitRow`).

Дальше — `Config/Animations.fallbacks` в игре сам подставляет Win/Lose/CrouchLight/CrouchHeavy/
AirLight/AirHeavy (Win→Idle, Lose→Knockdown, CrouchLight→Light и т.д.), поэтому рисовать их
отдельно не нужно — 12 рядов полностью покрывают все 18 анимаций.

## Как включить нарисованный арт в игре

Сам генератор только создаёт PNG на диске — Roblox не умеет грузить произвольные файлы
напрямую, картинки нужно один раз загрузить через Studio и получить `rbxassetid`:

1. Открыть проект в Roblox Studio.
2. Toolbox → **Import** (или Avatar → Bulk Import Tool) → выбрать **оба** файла
   `art/sprites/<id>_a.png` и `<id>_b.png`. Studio загрузит картинки и покажет их `rbxassetid://…`.
3. Вписать оба id в `src/shared/Config/CharacterSprites.luau` (там есть шаблон
   `sheet(assetIdA, assetIdB)` — просто добавить строку с нужными id для персонажа).
4. Сохранить — `CharacterRegistry` сам подставит спрайт-лист персонажу, `SpriteAnimator`
   переключится с процедурного `Rig` на `Sheet` автоматически. Ничего в бою менять не нужно.

Пока записи в `CharacterSprites.luau` нет — персонаж рисуется как раньше, процедурным `Rig`.
Можно переключать персонажей по одному.

**Важно:** если раньше уже загружали старые (96px, один файл) картинки — те `rbxassetid`
больше не подходят (другой размер и раскладка), их нужно перезалить заново по инструкции выше.

## Структура

- `lib/png.js`, `lib/crc32.js` — минимальный PNG-энкодер (без зависимостей).
- `lib/canvas.js` — холст супер-разрешения: заливка полигонов/капсул/кругов, даунсемпл,
  квантизация в палитру, обводка силуэта.
- `data/poses.js` — порт `RigPoses.luau` (позы Idle/Walk/…/12 базовых анимаций,
  все 16 особых приёмов по `special.kind`, все 6 суперов по `super.delivery`).
- `data/looks.js` — порт `CharacterLooks.luau` (облик/аутфиты каждого бойца).
- `data/characters.js` — сжатый порт `Characters.luau` (id, палитра, тип спешла/супера).
- `rig.js` — сам пиксельный рисовальщик: порт геометрии суставов `Rig.luau` (та же формула
  бёдра→корпус→шея→голова и т.д.), рисование тела/причёски/головного убора/лица/оружия.
- `generate.js` — сборка спрайт-листов, точка входа.

## Изменить стиль/добавить деталей

Вся отрисовка — в `rig.js` (тело, лицо, волосы, головные уборы, оружие, детали одежды по
`top.style`). Поправить что-то для всех персонажей сразу — значит поправить одну функцию
там (например `drawFace`/`drawHair`/`drawTorsoDetail`) и перегенерировать:

```bash
node tools/pixelart/generate.js         # все сразу
```

Если персонаж получит новый образ в `Config/CharacterLooks.luau` или новый особый приём —
достаточно перегенерировать его лист, менять `rig.js`/`poses.js` не нужно.
